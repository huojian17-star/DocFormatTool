# 02-发布流程

## 版本号规则

- **exe 内部版本** = 打包时 `license/version.py` 的 `VERSION`（窗口标题显示）
- **release 标签** = 必须与 exe 内部版本**一致**（用户下载后看到的版本号 = exe 内部）
- **version.json 的 version 字段** = 线上"最新版"（老用户检查更新的依据）
- 发布版本号**必须 > 所有已发布过的版本号**（包括测试版！）——窗口期用户升到过测试版 v1.0.13，正式版就用 v1.0.14 跳过它

## 发布完整步骤

1. **改版本号**：`python -X utf8 site/fix_ua_and_ver.py 1.0.14`（改 version.py）
2. **打包**：`python -X utf8 -m PyInstaller --noconfirm --clean DocFormatTool.spec`（3 分钟，后台跑）
3. **验证**：启动 dist exe → 窗口标题显示正确版本号
4. **复制到测试包**：`Copy-Item dist\DocFormatTool.exe F:\论文排版工具_测试包\DocFormatTool.exe`（**用户惯例：打包文件放测试包根目录，从那里上传**）
5. **用户上传**：
   - GitHub release（标签 = 版本号，附件名 DocFormatTool.exe）
   - 蓝奏云（更新 manual_url）
6. **我验证附件**：下载 release 附件算 md5，与本地 dist 对比**必须一致**（曾传错过 v1.0.13）
7. **更新 version.json**：version + full_url（ghfast + release 下载地址）+ sha256 + note + manual_url
8. **push + purge jsdelivr**（见 [[05-踩坑记录]] jsdelivr 缓存）
9. **验证线上**：raw 读 version.json 确认版本号

## version.json 结构

```json
{
  "version": "1.0.14",
  "url": "ghfast/raw/.../updater.exe",          // 旧版(<1.0.7)下载 updater
  "full_url": "ghfast/releases/download/vX/...", // 新版(>=1.0.7)下载完整 exe
  "sha256": "...",                                // 下载校验
  "note": "更新说明（老版本弹窗显示，含手动下载指引）",
  "manual_url": "蓝奏云链接",
  "manual_pwd": "提取码"
}
```

## 关键要点

- **note 必须写手动下载指引**（"若自动更新按钮无反应，用蓝奏云链接手动下载覆盖"）——老版本 exe 内置的更新代码是烧死的，只有手动下载一条路（见 [[03-更新链路]]）
- **update_urls 顺序**：ghfast → raw → jsdelivr（ghfast 国内可直连；raw 无缓存即时；jsdelivr 有 12h 顽固缓存需 purge）
- 版本比较 `_cmp_version` 支持 `1.0.1` 格式，字符串分割比较
