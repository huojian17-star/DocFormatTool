# 05-踩坑记录

## 开发环境/工具链

- **复杂操作先写 .py 脚本再运行**——PowerShell 内联 `python -c "..."` 引号转义地狱（中文引号/嵌套引号/$ 变量反复 SyntaxError）。`python -X utf8 site/xxx.py` 一步到位，可复用可调试
- **exe 里 print 不能用非 GBK 字符**（✓ ✗ 会 UnicodeEncodeError 崩）——用 [OK]/[FAIL]
- 装工具前先盘点：`ollama list` / `pip list`（已有 qwen3.5:latest 就别装 qwen2.5vl）

## 打包（PyInstaller）

- **conda Python + PyInstaller 是 LoadLibrary 重灾区**（conda DLL 依赖链指向 Library\bin）——本机实测 PATH 假说不成立（PyInstaller 收全了依赖），但社区公认风险，正式环境建议 python.org 官方 Python 打包
- onefile 的 _MEI 解压目录：强杀/崩溃会残留（曾积 15 个）——启动时清 2 小时前的 + 更新 bat start 前清
- UPX 一般不破坏依赖，但排查时可先关掉排除变量
- **onedir 备选**：`DocFormatTool_onedir.spec`（DLL 摊目录，彻底无 _MEI 问题，分发 zip + 整目录替换）

## GitHub / 网络

- **jsdelivr 对 master 缓存 ~12h 顽固**：改 version.json 后必须 `https://purge.jsdelivr.net/gh/...@master/version.json` 强制清
- **raw.githubusercontent.com 边缘缓存**：push 后可能需要几分钟刷新（加 query 参数可绕过，0.1s 响应 = 缓存命中）
- **push 失败不要连续盲试**：最多试 2 次，回头确认网络环境后再推
- ghfast.top 加速 raw 有缓存（可能返回旧版）——多通道设计（ghfast→raw→jsdelivr）靠"版本不新就 continue 下一通道"兜底

## 更新链路（详见 [[03-更新链路]]）

- **自动重启用 explorer 不用 start**（cmd 会话启动 GUI 的 DLL 加载差异 → LoadLibrary）
- bat 模板转义：`%%A`（for 变量）在 Python 字符串里要写 `%%%%A`；`%TEMP%` 要写 `%%TEMP%%`
- GUI download 曾漏传 sha256（用户下载损坏检测不到）——selftest 覆盖
- 弹窗 lambda 闭包：`lambda e=e:` 防延迟执行失效

- 交付物统一 docx（见 [[06-用户约定]]）
